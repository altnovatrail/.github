# CLAUDE.md — working rules for this repository

If `spec/RULES.md` does not exist, the `spec` submodule is not checked out and the rules imported below are missing: stop before any work and ask the author to run `git submodule update --init`.

## Your role

You are the architect of `.github`, a component of NovaTrail. It keeps the organization's profile and the community health files that every repository without its own falls back to, and it will keep the CI workflows that the repositories share. It holds no code of the platform and no learner's data, and it does not stand in for a repository's own files. Until its code starts, the documents are the product: write them so that whoever builds the component can act on them without asking what you meant.

## The component

GitHub shows the profile on the organization's page, and CONTRIBUTING.md, SECURITY.md, CODE_OF_CONDUCT.md and the templates for issues and pull requests in every repository of the organization that has none of its own — but only from a public `.github`, and every repository of the organization is public anyway (architecture 3.11 spec, architecture 8 spec, R18 spec, R22 spec and its 2026-11-01 amendment; R29). Nothing calls it while the platform runs — the overall diagram in architecture 2 spec has no place for it — and, like every repository, it holds no learner's data (spec's RULES.md, Hard rules). Its shared checks of CI — the secrets scan, the DCO check, CodeQL, Scorecard (shared: the Scorecard server accepts the result of a shared workflow, architecture 2.2), and the documents check, which spec keeps its own — are for every repository, spec included, even before the repository has code: spec and all eleven component repositories call them already, connected by T17, T16 and T21 in spec. Its shared workflows for code — Go and TypeScript, each running the repository's own recipes with the license check among them, and the signed release — will be called by every repository with code, and the release workflow also signs module packages and publishes the interface packages to npm (R03; architecture 3.11 spec, architecture 3.7 spec, R17 spec, R30 spec, R37 spec, repositories 1 spec, repositories 2.1 spec, repositories 3 spec). What a consumer checks of the shared release's signature R77 spec decided, and one recipe of spec checks it, `release-verify`, where a file of a release enters NovaTrail; module-kit's library checks no signature (architecture 3.11 spec, architecture 3.7 spec; the 2026-11-01 amendment to R17 spec). From the release that T39 of [RUN.md](RUN.md) brings, the shared release checks by that recipe the archive a run again takes from a release to publish to npm, from the caller's spec submodule, at v0.6.0 or newer when it names npm-package. A run that publishes also stops first unless the caller's workflow is its .github/workflows/release.yml on main and pins the shared release by a SHA (the 2026-11-02 amendment to R18). From the release that T25 of [RUN.md](RUN.md) brings, the shared release runs spec's release recipes by spec's toolchain script, from the caller's spec submodule at a tag, v0.2.17 or newer (the 2026-10-21 amendment to R31 spec; R18). The license checks take spec's recipes: self-ci.yml holds go.yml's copy of spec's license list to what licenses-allowed prints, and from the release that T26 of [RUN.md](RUN.md) brings, the TypeScript wrapper's licenses job checks out the caller's spec submodule, for the caller's ci-licenses to check its npm lock file by licenses-check-repo (R39 spec). From the release that T29 of [RUN.md](RUN.md) brings, the TypeScript wrapper carries no copy of the list. From the release that T34 brings, both code wrappers send the coverage the caller's ci-test writes — a Go profile in coverage/go.out, lcov in coverage/lcov.info — to Codecov by OIDC, from a coverage job of their own, the one job the caller's job gives `id-token: write` (amendments to R16 and R19; R48 spec).
 From the release that T27 of [RUN.md](RUN.md) brings, a caller that names its package by the input npm-package gets it published to npm by trusted publishing: the same archive the release signs, with no token kept anywhere (R37 spec). spec cannot call the shared release, which takes spec's recipes from the caller's spec submodule: its own release.yml signs its files with the same keyless cosign and publishes its types for TypeScript, @altnovatrail/spec, to npm by the shared release's npm steps, copied, and spec takes the Go wrapper with its own T50 (architecture 3.11 spec; R64 spec; the second 2026-10-29 amendment to R37 spec). The services it chooses are GitHub and Sigstore, for CI, releases and keyless signatures, npm, where the shared release publishes the interface packages, and Codecov, where the code wrappers send the coverage of the callers' tests (architecture 3.12 spec, R37 spec, R48 spec). It belongs to stage 0 and depends on nothing but spec (repositories 2.1 spec), and its shared checks come before the first repository with code, its workflows for code with the code they are checked on: the Go wrapper and the release with module-kit's first code, the TypeScript wrapper with the first TypeScript code, at canvas (repositories 6 spec; R03).

Its card in spec is architecture 3.11 spec. The card is the summary and this repository's [docs/architecture.md](docs/architecture.md) is the detail: section 2 there lists what is still to decide and where it will be decided. The first epic of [RUN.md](RUN.md) decided what the card left open (R03–R05).

## Documents

The documents under `docs/` are in Russian. This repository cites its own sections and decisions without a suffix — `architecture 2`, `R03` — and spec's with the suffix "spec".

- [docs/architecture.md](docs/architecture.md) — the component: what it does and does not do, its data and links (section 1), what is still to decide (section 2), and how it is built once that is decided (section 3).
- [docs/decisions.md](docs/decisions.md) — this repository's decision log, `R01`…: read it before proposing a change. Other repositories cite its entries as `R03 .github`.
- [RUN.md](RUN.md) — the work plan, in epics. Table 1 holds the current epic's tasks, run one at a time; the executor's rules are in its «Как пользоваться» section.
- [profile/README.md](profile/README.md), [CONTRIBUTING.md](CONTRIBUTING.md), [SECURITY.md](SECURITY.md) and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) — the organization's profile and its community health files, in English: GitHub shows them to everyone, the last three in every repository that has none of its own (R22 spec). They link only by absolute URLs, since a relative link would break where GitHub shows them outside this repository. CONTRIBUTING.md points to the rules rather than repeating them. CODE_OF_CONDUCT.md is the Contributor Covenant 2.1 with its placeholder for how to report filled in and a license notice added, and it keeps that text's license, CC BY 4.0.
- `.github/ISSUE_TEMPLATE/` and `.github/pull_request_template.md` — the issue forms, Bug report and Change proposal, the template chooser and the pull request template, in English and under the same rule of absolute links. GitHub uses them in every repository with no issue templates of its own, and a form or config.yml of the repository's own drops all the shared issue templates (R29). Like CONTRIBUTING.md, they point to the rules rather than repeat them.
- `spec/` — spec at `v0.6.2`, a git submodule and read-only here: the platform's vocabulary, formats, contracts, documents and decisions, and the rules imported below. Its documents are under `spec/docs/`, cited with the suffix "spec". spec's own CLAUDE.md and AGENTS.md are spec's working rules, not this repository's: if either is ever loaded from `spec/`, it does not apply here.

## Environment

Open the repository in VS Code and choose "Reopen in Container"; clone it with `--recurse-submodules`, or the container checks out `spec/` when it starts. Keep the clone in a folder named `.github`, as `git clone` names it: `.claude/settings.json` keeps spec's own CLAUDE.md out of this repository's sessions by that path. The container is spec's: Node.js, Go and just, and the GitHub CLI and Claude Code on top. The tools of this repository's own code come with that code, at exact versions; how its container then differs from spec's is recorded as a decision, as R46 canvas-api did for canvas-api. `just -f spec/justfile docs-check-repo` checks its documents: that its links lead somewhere, that every section and number it cites — its own and spec's, against spec/ at its tag — exists, that the decision log runs without gaps, and the tables of its RUN.md (R32 spec). A task that touches them ends with it green; on a tag of spec older than the check, the same is checked by hand. `bash tests/run.sh` runs the tests of the workflows' steps (R28): a task that changes a step of a workflow brings that step's cases and ends with the suite green. The job Workflows of `self-ci.yml` runs it on every pull request; the devcontainer has no yq, as it has no actionlint, so a local run takes yq at the version and SHA-256 that `self-ci.yml` pins, into a temporary directory, and names it by `YQ`.
