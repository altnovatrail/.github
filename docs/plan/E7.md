## Эпик E7. Публикация в npm в общем релизе

**Почему эпик такой.** `spec` закрыл Т-26 решением R37 spec (Д13 в RUN.md `spec`). Пакеты интерфейса выходят в npm, в области `@altnovatrail`, тем же файлом, что подписан в релизе GitHub, — шагом общего `release.yml`, а не своим job в каждом репозитории с пакетом. Как шаг устроен, решает `.github`: общие workflow — его (R03). Первым шаг позовёт T24 canvas — публикация `@altnovatrail/canvas`.

**Не входит:**
- первая версия `@altnovatrail/canvas` и trusted publisher у пакета — шаги автора в T24 canvas: trusted publisher настраивается у пакета, который уже есть в реестре;
- пакет типов `spec`: где он выходит, решает T35 `spec`;
- что потребитель проверяет у подписи — Т-27.

#### T27. Публикация в npm в общем релизе

- **Цель:** общий `release.yml` публикует в npm файл пакета, который назвал вызывающий, — тот же, что подписан в релизе GitHub, — через trusted publishing и без долгоживущего токена. Это поправка к R18. Шаг вышел релизом `.github`, а в architecture 3.3 есть вызывающий с ним.
- **Почему:** ответ `spec` на Т-26 — R37 spec. Его ждёт T24 canvas.
- **Что просит `canvas`** — `spec` записал это в R37 spec:
  - шаг идёт на раннере, а не в стадии `toolchain` вызывающего: туда токены не идут (R18);
  - Node и npm — по точной версии и с суммой в самом файле, как cosign (R18), и не ниже npm 11.5.1 и Node 22.14.0: этого требует trusted publishing;
  - шаг идёт, только если вызывающий назвал файл пакета. Первую версию публикует автор руками: trusted publisher настраивается у пакета, который уже есть в реестре;
  - `--access public` — явно; при `publish: false` шаг ничего не публикует;
  - на повторе прогона шаг берёт файл из релиза и сверяет подпись. Опубликованную версию он не публикует заново, а сверяет по `integrity`. Версию ниже новейшей в npm ставит не под `latest`. При отказе, который пропускает `release-refusal`, ничего не публикует.
- **Решить при планировании:**
  - вход с именем файла пакета в `dist/` и его проверка;
  - откуда Node и npm: архив Node с nodejs.org с суммой в файле и npm, который идёт с ним, или отдельная версия npm;
  - provenance: как его даёт trusted publishing и нужен ли флаг — по документации npm, с датой прочтения;
  - `id-token: write` нужен обоим workflow, вызывающему и общему (R37 spec). У вызывающего job он уже есть — ради cosign (architecture 3.3);
  - проба без публикации — `publish: false` и `npm publish --dry-run`. Нужна ли до T24 canvas настоящая публикация пробного пакета: это действие вне репозитория, и его не отменить — версия в npm неизменна (правило 4);
  - нужны ли шагу или вызывающему выходы общего `release.yml` — версия и признак, что релиз вышел.
- **Решено автором (2026-10-22), при планировании:**
  - вход — имя пакета, `npm-package: "@altnovatrail/canvas"`, а файл — тот, которому даёт имя `npm pack`: `altnovatrail-canvas-<X.Y.Z>.tgz`. Отвергнуто имя файла с местом под версию: у вызывающего появился бы свой шаблон;
  - настоящей публикации в этой задаче нет: первую делает T24 canvas, а её итог дописывается сюда. Отвергнут пробный пакет с пробным вызывающим: это действия вне репозитория, и версию в npm не отменить (правило 4);
  - npm верит файлу workflow вызывающего по имени, с любой его ветки. Это принято и записывается в поправку к R18. Окружение с правилом веток — когда у репозиториев появятся другие участники с правом записи;
  - ветки, пробу, коммиты, pull request и мерж делает исполнитель, а сама задача идёт сразу за этой записью.
- **Выяснилось при планировании** (прочитано 2026-10-22 — документация npm, исходники npm, документация GitHub, реестр npm и API GitHub; источники с коммитами войдут в architecture 4):

    - настройка, созданная после 2026-09-03, по умолчанию разрешает только `npm stage publish`, и прямой `npm publish` отмечают явно;
    - новая настройка должна пройти первую публикацию за 2 дня, а пакет должен уже быть в реестре;
    - provenance npm создаёт сам, если OIDC прошёл, а репозиторий и пакет публичные, и флаг `--provenance` не нужен;
    - `repository.url` в `package.json` должен совпасть с репозиторием;
  - npm CLI 11.19.0 — тот, что идёт с Node 24.21.0, — и 11.19.1. Между ними код OIDC и публикации не менялся (`gh api repos/npm/cli/compare`):

    - версию ниже старшей в реестре без явного `--tag` npm с 11.0.0 не публикует;

- **Решено при планировании** (исполнителем, по рекомендациям; решения проверил агент планирования, и его поправки вошли сюда):
  - **вход `npm-package`**, по умолчанию пустой — тогда шагов npm нет, и вызывающий без него ничего нового не видит. Имя проверяется на каждом прогоне, первым шагом: `^@altnovatrail/[a-z0-9][a-z0-9._-]*$`;
  - **cosign — свой шаг:** он нужен и подписи, и повтору прогона;
  - **Node 24.22.1** — архив с nodejs.org с суммой в файле, как cosign (R08), и его npm 11.19.1. Отвергнуты:
    - v24.21.0, как в Dockerfile: шагу с правом публикации нужен последний выпуск с исправлениями безопасности;
    - `actions/setup-node`: не закреплён суммой, как и cosign-installer (R18);
    - Node раннера: он не закреплён;
  - **повтор прогона** — коммит уже выпущен, и `publish: true`. Шаг берёт архив и его `.sigstore.json` из релиза (`gh release download`; `GH_TOKEN` — только здесь), затем `gh release verify-asset` и `cosign verify-blob`. Identity — общий `release.yml` на любом SHA, по regexp, с издателем, репозиторием и коммитом `TARGET`: кнопка может идти с другой закреплённой версией общего файла. Что этот SHA — релиз `.github`, решает Т-27;
  - **проверка архива — до релиза GitHub**, без токенов:
    - файл есть, всё в нём лежит под `package/`, а `package/package.json` один;
    - имя — вход, версия — номер без `v`;
    - нет `private: true`, `publishConfig` и верхнего `tag`;
    - `repository` — объект, и его url без `git+` и `.git` — `https://github.com/<репозиторий>`;
    - реестр читается запросом packument и `jq`, а не `npm view`:
      - пакета нет — при `publish: true` ошибка, ведь первую версию публикует автор;
      - версия есть с той же `integrity` — публиковать нечего;
      - версия есть с другой `integrity` — ошибка: номер в npm уже не вернуть;
    - версия ниже старшей неустаревшей X.Y.Z реестра идёт с `--tag previous`, а `latest` явно не ставится никогда;
    - затем `npm publish --dry-run --json`, и имя файла и `integrity` в его ответе должны совпасть;
  - **изоляция npm:**
    - пустая папка в `RUNNER_TEMP`, и `--userconfig`, `--globalconfig` и `--cache` — там же;
    - без переменных `npm_config_*`, `NODE_OPTIONS` и `NPM_ID_TOKEN`;
    - с `--registry` и `--@altnovatrail:registry`;
    - node и npm — по пути, с `--ignore-scripts`.

    Так npm не читает `.npmrc` вызывающего и не уходит в другой реестр. Это защита от чужих настроек, а не от кода, который шёл на раннере раньше (В23);
  - **у пробы нет токена:** проверка идёт без `ACTIONS_ID_TOKEN_REQUEST_*`, поэтому `--dry-run` токена npm не получает, хотя обмен и пробует. Токен шаг получает только в «Publish to npm», а тот идёт только с `publish: true`;
  - **публикация** — после «Verify the release»: `npm publish <файл> --access public [--tag previous] --loglevel verbose`. Вердикт — реестр, а не код выхода npm: шаг спрашивает packument раз в 10 секунд, до 5 минут.
    - Та же `integrity` — успех, и архив из реестра сверяется с файлом `cmp`.
    - Другая — ошибка.
    - Версии нет — шаг называет вероятную причину: версия только staged (npm/cli#9889 или trusted publisher без прямой публикации) или отказ OIDC, — и что нужно в настройке.
    - Нет provenance — предупреждение;
  - **публикации нет** после отказа, который пропускает `release-refusal`, и при `publish: false`;
  - **выходов** у общего `release.yml` нет: шаг внутри него, и вызывающим они не нужны;
  - **граница доверия** — в поправку к R18. npm верит файлу вызывающего с любой ветки. На раннере npm разбирает архив, который собрал код вызывающего, а переменные OIDC у job есть всегда, — рядом с В23;
  - **npm под Artistic-2.0** — исключение для инструмента CI в поправке к R18, как ShellCheck в R08. Что npm без названного исключения есть в каждом devcontainer, — В26 «в реестр spec»;
  - **проба** — pull request без мержа, как #54: `publish: false`, `npm-package: "@altnovatrail/release-trial"`, пробный пакет в корне и `release-files`, который делает `npm version` и `npm pack`. Положительный прогон и семь отрицательных:

    - N4 — имя без области;
    - N5 — чужой репозиторий;
    - N6 — `publishConfig`;
    - N7 — `private`.
