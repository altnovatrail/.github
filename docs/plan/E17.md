## Эпик E17. Кеш образа стадии toolchain

**Почему эпик такой.** Каждый job общих `go.yml` и `typescript.yml` собирает образ стадии `toolchain` из `.devcontainer/Dockerfile` вызывающего, а `documents.yml` — скриптом `toolchain.sh build` подмодуля `spec`. Сборка качает Node с nodejs.org, архивы с github.com и пакеты из снимка архива Ubuntu, и 2026-11-09 сбой сети уронил её у `canvas` и у `spec`: «`curl: (22) The requested URL returned error: 504` после трёх повторов, в трёх попытках из четырёх прогона CI 42569536919» (поправка 2026-11-09 к R31 spec). `spec` решил брать образ из кеша, как R57 canvas, и поручил `.github` «своей задачей и релизом» (Д146 в RUN.md `spec`; строка 2.4 COORDINATION.md):
- в `go.yml` и `typescript.yml` — те же шаги кеша по тому же ключу вокруг своей сборки образа;
- в `documents.yml` — шаги вокруг `toolchain.sh build` тега `spec` с T104;
- общий `release.yml` кеша не берёт.

Задач две, потому что вторая ждёт `spec`, а первая — нет.

**Что известно** (прочитано 2026-11-09):
- **образец — R57 canvas** (`main` 66266e1 `canvas`): шаг `actions/cache/restore` с ключом `toolchain-${{ runner.os }}-${{ runner.arch }}-${{ hashFiles('.devcontainer/Dockerfile') }}`; шаг, который грузит файл `docker load`, а без файла или с файлом, который не загрузился, удаляет его, собирает образ и пишет `docker save`; шаг `actions/cache/save` при `cache-hit != 'true'` с ключом из `cache-primary-key`. Шаги — прямо в workflow, без своего составного action, чтобы Dependabot `github-actions` видел их без правки `dependabot.yml`. `actions/cache` — v6.1.0, коммит 55cc834, лицензия MIT;
- **у `.github`** образ собирают пять job `go.yml` — `check` (матрица рецептов), `targets`, `fma-diff`, `arm64` на `ubuntu-24.04-arm` и `rules`, — и `check` `typescript.yml` (матрица), каждый шагом «Toolchain image»: `docker build --target toolchain --tag toolchain - < .devcontainer/Dockerfile`. Job `coverage` образа не собирают. `documents.yml` зовёт `spec/tools/toolchain/toolchain.sh build`, а скрипт называет образ `novatrail-toolchain`;
- **версия записи кеша** — хеш пути и способа сжатия: «The cache is scoped to the key, version, and branch», и одинаковый ключ с другими `path` даёт другую запись (README `actions/cache` v6.1.0, «Cache scopes», «Cache Version»). Сбой сохранения `actions/cache/save` пишет предупреждением, а не ошибкой job (`src/saveImpl.ts` v6.1.0);
- **области:** запись pull request видна только ему, а запись `main` — всем pull request; область `main` вызывающего наполняет его прогон CI на push в `main` (поправка 2026-11-09 к R31 spec, с цитатой из GitHub Docs, Dependency caching reference);
- **проверка на себе:** `self-ci.yml` зовёт `./.github/workflows/go.yml` и `./.github/workflows/documents.yml`, так что кеш этих двух `.github` пробует на своём pull request; `typescript.yml` в `self-ci.yml` не зовётся.

**Не входит:** кеш в общем `release.yml` и в `self-release.yml` — отвергнут поправкой 2026-11-09 к R31 spec; кеши Go и npm внутри job.
