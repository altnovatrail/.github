# Security policy

This policy holds in every repository of [altnovatrail](https://github.com/altnovatrail) that has no SECURITY.md of its own.

## Supported versions

Fixes go to each repository's default branch, `main`. A repository that publishes releases ships a fix in its next release, and its earlier releases get none: only its latest release is supported, and the repository's **Releases** page names it. Report against the default branch, and if you found the vulnerability in a release, name that release.

## Reporting a vulnerability

Report it privately, through GitHub's private vulnerability reporting:

1. On the repository's page, open the **Security and quality** tab.
2. Click **Report a vulnerability** — GitHub shows it on the tab's **Advisories** page — and fill in the form.

The report goes privately to the repository's maintainers. Please never report a vulnerability in a public issue, discussion or pull request. GitHub's guide is [Privately reporting a security vulnerability](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability).

If a repository shows no **Report a vulnerability** button, open an issue that asks for a security contact, without any detail of the vulnerability.

## Learners' data

NovaTrail is built for learners of any age, children among them. If a vulnerability exposes a learner's data, describe what is exposed and where, but do not copy the data into the report.

## What happens next

The maintainer gives a first response within 14 days of the report, in the advisory that the report opens: that the report has arrived and is being looked into. The 14 days are for that response, not for the fix. The maintainer then works out the fix with you there and publishes the advisory once the fix is out, crediting you if you wish. There is no bug bounty.
